# 参数关系分析与验证

`/parameter-relations` 将处理过程分成两个明确阶段：先离线分析所有候选关系，
再对已就绪的小批接口对执行有预算上限的验证。全量分析不会自动调用项目里的
全部接口。

## 全量本地分析

后台分析任务会从导入资产、脱敏流量样本和人工结论中发现候选关系，计算字段
方向、定位器、环境、认证上下文和数据就绪度，并将关系归入 `auto_ready`、
`needs_data`、`needs_context`、`needs_correction` 或 `policy_blocked`。

任务状态、游标、计数和租约持久化保存，因此页面关闭或服务重启后仍可恢复。
该阶段不得调用认证接口或业务接口。

## 有界验证

一次验证案例由“来源接口 -> 消费接口”构成；同一接口对的多个字段共享来源请求
和消费请求，不按字段重复发送。

- 普通批次只选择 `auto_ready` 接口对；需要审批的关系不会自动再次入队。
- 默认只允许 `GET`、`HEAD` 和 `OPTIONS`；变更型方法需要显式批准，且环境、
  账号、Fixture 和清理策略都必须允许。
- 创建批次前冻结有序接口对、方法、路径、Host、字段数和逐对预算；确认范围与
  预览不一致时拒绝执行。
- 来源阶段失败时不得注入字段，也不得发送消费请求。
- Host 切换只能发生在同一已授权环境范围内，并受请求硬预算约束。

HTTP 结果分类遵守以下原则：普通 400 不自动等于路由错误；只有明确的结构化
业务错误才停止跨 Host。401/403 作为认证或角色阻塞，429 作为限流，409/422
作为业务语义拒绝。404/405/421 以及请求发出前的连接、证书或 URL 错误，可以
在剩余授权 Host 与预算内继续验证。

## 失败提示与恢复

| 情况 | 持久化状态 | 后续动作 |
| --- | --- | --- |
| 参数、环境、CSRF 或预算预检失败 | 未创建运行或安全失败编号 | 修正输入并重新预览 |
| 认证上下文不可用 | `paused`，请求计数为 0 | 修复认证后恢复原运行 |
| Host 范围不足 | `host_scope_approval_required` | 审批新增范围和预算 |
| 来源数据缺失 | `needs_data` | 补充来源 Fixture |
| 来源或消费请求被业务拒绝 | 结构化失败阶段与错误类别 | 修正 Fixture、角色或参数 |
| Worker 异常 | `failed` 与安全错误编号 | 依据编号检查本地日志 |

执行结果只保存脱敏请求结构：方法、Origin、Path、Query/Header/Cookie 名称、
Body 字节数和 Content-Type、TLS、跳转、超时、认证前置请求数、HTTP 类别和
耗时。Token、Cookie 值、Query 值、Body 原文、注入值及响应正文只能短暂存在于
Worker 内存或仓库外的受控证据存储中。

## 公开仓库验收

公开测试使用 `example.test` 域名、合成项目、合成响应和本地替身服务，至少覆盖：

1. 离线分析不发出网络请求，且任务可停止、续跑；
2. 预览不创建运行，确认后执行范围与预算不可变；
3. 多字段复用一次来源请求；来源失败时消费请求数为 0；
4. 普通 400 与明确业务拒绝的分类不同；
5. 认证、Host、限流、Fixture 和 Worker 故障均可形成可恢复状态；
6. 结果、页面、日志和测试制品中不出现凭据值、响应正文或私有证据路径。

真实目标的授权验证记录、运行 ID、目标 Host、接口路径和响应特征必须保存在
`API_MANAGER_DATA_DIR` 指向的仓库外目录，不进入 Git 历史。
